Preview, a demonstration control, and a live sign control can look similar while affecting different targets. Confirm which one you have before selecting an action.

## Before you begin

Have authorized access to the intended layout or sign and know whether you are practicing in a demonstration or working with a physical screen. For a live-sign test, arrange an on-site observer and permission for the planned change.

## Identify the target

| View or control | What to confirm |
| --- | --- |
| Layout Preview | You are viewing the intended layout in a browser. This does not establish what a physical screen is showing. |
| Layout or demonstration Remote Control | The control is intended for the particular preview or demonstration you are using. Confirm its scope before interacting. |
| Sign Remote Control | The control targets the intended physical player, and you are authorized to affect its display. |

## Check before using the control

1. **Start with the intended task.** Decide whether you need to inspect content, rehearse a demonstration, or operate a live sign. Use the view or control supplied for that task.
2. **Confirm the target identity.** Match the layout or player identifier to the target you intend to use. If a shared link or QR code does not make its scope clear, ask its owner or support.
3. **Review the permitted actions.** A control link may allow active changes. Do not assume that a QR code is a read-only preview or that a control labelled for a layout is safe for every environment.
4. **Make one authorized test.** In an approved demonstration, use a simple content change that you can observe. For a live sign, agree on the change with the person responsible for that screen first.
5. **Observe the intended result.** A change in the browser confirms that browser view changed. For a live-sign test, have the on-site observer confirm the physical screen. Record a mismatch rather than switching to another control by guesswork.
6. **Finish in the agreed state.** Return the demonstration or screen to the state agreed for the test, using the instructions for that setup.

## Expected result

You know which target the control affects and have confirmed the permitted action on that target. A successful demonstration has not been mistaken for proof that a live sign changed.

## When to contact support

Contact [EditNew Support](https://support.editnew.ca) if the target is unclear, a control appears to affect a different view, or the expected screen does not respond. Provide the layout or player identifier and describe what changed in each view.

Keep production control links and QR codes limited to the people authorized to use them.
