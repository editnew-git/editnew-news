## When this applies

Use this guide when a copied layout loads incorrectly or its presentation control fails while other controls may still work. This is an evidence-gathering procedure, not a general repair for remote controls.

## Before you begin

Have the original and copied layout identities available. Preserve the current layout and do not remove media items simply because another layout had a similar symptom.

## Record the failure

1. Confirm the copied layout's ID and the account in which it is opened.
2. Record the specific action that fails and the content you expected to appear.
3. Note whether the original layout behaves differently and which other controls still work, if those checks are authorized.
4. Capture the exact visible error. If an error mentions an adspot, include that text in the support report.
5. Record the observation time and timezone and provide screenshots with private account information concealed.

## What support needs to verify

A missing adspot reference has caused one documented copied-layout failure. Support must identify the actual reference in the affected layout before deciding whether to repair or remove anything. A similar symptom does not establish the same cause.

## Expected result and stop point

You have a reproducible report tied to the correct layout. Contact support for the repair and agree how rendering and the intended presentation action will be checked afterward. Do not copy item or module numbers from another incident, or treat a layout-copy test as verification of emergency-alert delivery.
