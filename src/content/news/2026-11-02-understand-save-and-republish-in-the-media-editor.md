Saving an edit, publishing generated content, loading Preview, and showing an update on a physical screen are separate checkpoints.

## Save the form you are editing

For a **Text/HTML** item in Media:

1. Open the intended existing item and edit its text.
2. If you use **Source code**, select that dialog's **Save** to return to the text editor.
3. Select the Media editor's main green **SAVE** to commit the item. Source-dialog Save alone does not complete this edit.
4. Reopen the same item and verify the actual saved text and formatting.

The upload dialog, item settings, and Module Manager have their own controls. Do not assume every operation uses the same Save sequence. In particular, a confirmed individual-media deletion is different from a text edit or a staged module removal.

For **Upload Image(s)**, select the upload dialog's green **Save** after choosing a file. In that form, the uploaded image persisted after reopening Media without a second click on the toolbar's main SAVE. See [Upload an image to a S.A.M. layout](https://support.editnew.ca/news/2026-07-21-importing-content-in-runsam-uploading-images-to-a-layout/).

## Check the layout's Preview

Open **Preview** from the intended layout and reload it after saving. Wait for the relevant playlist item and compare it with the saved editor.

The text editor's toolbar Preview is a separate control. An already-open layout Preview may also retain an older version until it is reloaded. A normal reload can be enough to show a saved change; Republish is not required after every Save.

## Use Republish only when it applies

Some Media toolbars have an arrow beside green **SAVE** that opens a menu containing **Republish**. Match the actual menu shown in your form; do not assume that embedded and standalone toolbars always have different controls.

If support's instructions call for Republish:

1. Save and reopen the intended content first.
2. Open the arrow beside **SAVE** and select **Republish** once, when that option is present.
3. Reopen the saved item and confirm its content is still correct.
4. Reload the layout's Preview and check the intended item.
5. Verify the assigned physical display separately.

If the option is missing, ask support for instructions matching your form. Do not choose a different action by guesswork.

## When the results disagree

Republish does not save an unsaved source-code draft. A publication timestamp does not prove that a browser or physical screen has loaded that revision, and repeated Republish is not a confirmed remedy for an offline player.

Use [Check why Preview still shows old content](https://support.editnew.ca/news/2026-11-02-check-why-preview-still-shows-old-content/) for a saved-editor/Preview mismatch, or [Verify a saved update on the physical display](https://support.editnew.ca/news/2026-11-02-verify-a-saved-update-on-the-physical-display/) for the screen check.

Contact [EditNew Support](https://support.editnew.ca) with the layout identity, Save time, saved-editor result, fresh-Preview result, and physical-screen observation when available.
