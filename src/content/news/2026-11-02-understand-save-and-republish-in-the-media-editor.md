Saving an edit, generating published content, loading Preview and displaying it on a physical screen are separate checkpoints.

## Save the content first

For a Media Text/HTML item, Save in the source-code dialog returns the edit to the text editor. The main green **SAVE** commits the item. Reopen the same item and read its actual saved content before investigating publication.

A normal Preview reload may be enough to show an already-saved change. An open Preview tab can still display an older version.

## When the Republish control is available

The documented standalone Media form exposes **Republish** in the arrow menu beside green SAVE. Embedded or compact forms can have a different toolbar. If your form does not show that control, ask support for the matching instructions.

1. Save and reopen the intended content.
2. If republishing is part of your support instructions, open the arrow beside SAVE and select **Republish** once.
3. Reopen the saved item and confirm it still contains the intended content.
4. Reload the layout's Preview and wait for the relevant playlist item.
5. Verify an assigned physical display separately.

## What Republish does not establish

Do not use Republish as a substitute for saving an unsaved edit. A publication timestamp does not prove that a browser or physical display has loaded the change. Repeated republishing is not a confirmed cure for an offline player or every stale Preview. Contact support with the layout ID, Save time, saved-editor result and Preview result when those checks disagree.
